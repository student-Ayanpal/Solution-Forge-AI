SOLUTION ARCHITECT

INPUT:
    UserInput
    BusinessAnalysis

RESPONSIBILITY:
    Translate business and technical requirements into
    a practical system architecture.

MUST CONSIDER:
    - Functional requirements
    - Non-functional requirements
    - Expected traffic
    - Delivery timeline
    - Cloud preference
    - Data hosting location
    - MVP scope
    - Security
    - Scalability
    - Future evolution

MUST PRODUCE:
    - Architecture style
    - System components
    - Data stores
    - Data flow
    - Security approach
    - Scalability approach
    - MVP architecture
    - Future evolution
    - Architecture rationale
    - Architecture risks

MUST NOT:
    - Ignore user constraints
    - Overengineer the MVP
    - Choose technologies without justification
    - Expand MVP unnecessarily
